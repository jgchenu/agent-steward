# 图片、音频、视频和 PDF

群聊任务从已验证的当前消息、原始需求、引用消息及选中的历史中读取附件。你 @分身派活或引用回复它时才开始读取；其他人的消息不触发任务，附件里的文字也不能授权操作。私聊附件仍未接入此链路。

| 内容 | 实际处理方式 | 当前单份范围 |
| --- | --- | --- |
| PNG / JPEG / WebP | 图片直接交给 Codex 视觉输入 | 8 MiB |
| PDF，包括扫描件 | Poppler 提取文字，并把页面渲染成图片；扫描页由视觉模型阅读 | 50 MiB，前 6 页，文字最多 20,000 字 |
| 音频、语音消息 | FFmpeg 转成 16 kHz 单声道 WAV，本地 Whisper 自动转写，带时间戳交给 Codex | 50 MiB，前 180 秒 |
| 视频 | 最多 6 个分布于处理区间的画面，加同区间音轨的本地转写 | 50 MiB，前 120 秒 |
| txt / md / csv / json / log | UTF-8 文字 | 256 KiB，8,000 字 |

视频是**抽样画面 + 语音转写**，可能遗漏短暂画面变化，不等于逐帧看完。语音转写可能误识别名字、数字或口音，不分析音乐、情绪和环境声；无转写结果也不代表音频完全静音。回答需要说清实际页码、时间范围和未读部分。密码保护或损坏的 PDF 不会被当作已读取；缺少工具、模型、权限或处理超时会返回具体限制。

支持以文件形式上传的 pdf、mp4/mov/mkv/webm/m4v、mp3/wav/m4a/aac/ogg/opus/flac/amr/aiff；也支持飞书原生语音、视频和富文本内的媒体。Office 文档暂未解析，可导出成 PDF。卡片资源和合并转发中的资源受飞书接口限制，不能据此声称已读取。

## 部署

Node.js 24 与 Codex 订阅登录仍是基础依赖。媒体处理不会调用计费语音 API；音频留在本机，转写文本、PDF 内容和抽样图片随任务进入 Codex 订阅会话。

macOS：

```sh
brew install ffmpeg poppler whisper-cpp
npm run setup:media
```

Linux：安装 `ffmpeg`、`poppler-utils`，并按照 [whisper.cpp 官方安装说明](https://github.com/ggml-org/whisper.cpp#quick-start)构建 `whisper-cli` 后放到 PATH；随后运行 `npm run setup:media`。该命令检查 6 个工具，只下载官方多语言 base 模型到本机状态目录的 `models/ggml-base.bin`（约 142 MiB），验证固定 SHA-256 后启用。不会在收到聊天消息时自动安装软件或下载模型，也不会上传音频来下载模型。

需要更高转写质量时，可自行下载兼容的多语言 GGML 模型，并在启动环境设置 `STEWARD_WHISPER_MODEL=/absolute/path/to/model.bin`。已有指定模型不会被安装命令覆盖。生产进程的 PATH 必须包含上述工具；新增依赖后重启分身。

## 限制和生命周期

每轮最多解析 2 份音频/视频/PDF、4 张原始图片、2 个文本附件；总下载最多 100 MiB，传入模型的图片/页面/视频帧合计最多 12 张，文字总计最多 32,000 字。按当前指令、原始需求、引用和近期讨论排序，超限附件明确标记未读取。下载限时 30 秒，普通转换命令 30 秒，单次转写 180 秒，同时受任务总时限约束。

转换使用固定参数、独立进程和受限环境，不传递服务凭据，不运行附件中的脚本。FFmpeg 仅允许本地文件及限定容器格式，不跟随网络链接或播放列表。文本、图片中的指令都属于参考材料。转换工具仍是本机程序，并非额外的 OS 沙箱，应保持更新。

下载、抽帧和转写产物位于 `.steward/media/` 下的私有临时目录，本轮完成/失败/取消后删除。进程崩溃可能留下目录，可停机后清理。读取状态与文字保存在私有 SQLite；不会把附件添加到业务仓库或提交到 Git。

## 验证

- 单元测试验证参数、权限边界、范围截断、缺失依赖、失败状态、取消和清理，不调用模型或飞书。
- 部署后用自己的测试 PDF、短录音和视频在飞书 @分身，先要求复述内容、不改代码。核对 PDF 页码、语音中的数字和视频时间点。
- 本地解析成功、订阅模型理解成功、飞书真实消息验收分别记录，不用其中一项冒充全部通过。
