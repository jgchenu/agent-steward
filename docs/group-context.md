# 群聊、话题与自动上下文

群聊是可选功能。在私人 `steward.config.json` 顶层设置 `"groupChats": true` 后重启服务。默认关闭，新安装的私聊模式不需要额外群权限。

## 使用方式

- 把应用机器人添加到需要工作的群，主人直接 **@机器人 + 任务要求**，例如“分析上面的讨论，给我三条建议”，无需工作台关键字。
- 先在[本地授权页](workspaces.md)选择可用项目与默认空间。自然语言明确提到唯一已授权项目的名称或别名时进入该项目，否则使用默认空间或唯一项目；确实有多个候选时只需点选一次，完整需求保留（最多 16,000 字符）。
- 只 @机器人不说内容时，机器人会简短询问需求。原来的“工作台”表单是可选入口。
- 任务轮到执行时，先在你的原消息上添加“在做了”（OnIt）表情，再开始读取上下文和调用 Codex。正常执行不发送排队/开始卡片；结果和普通澄清问题以正常消息在话题里回复，Markdown 正常显示，长回复自动分段，不再用“待验收”表单包装日常回答。只有权限请求、项目选择和主动查任务时才显示必要卡片。表情只是接单回执，不代替最终验收状态。表情权限或网络不可用时改用一句话回执，任务仍继续。
- 在已有讨论话题里 @机器人，会读取该话题。普通群时间线发起时，会读取当前群最近的讨论。可以引用文字、富文本或卡片消息；消息图片及富文本内的截图会作为独立图片输入传给 Codex，支持的文本附件会读取正文。不自动打开链接。
- 进度、问题、交付和操作卡片回复到发起任务的话题里。在这个话题里，主人再次 @机器人，或使用飞书“回复”功能引用机器人的消息，可继续同一任务、同一 Codex 会话。普通话题发言不会自动续跑。
- 若任务正在执行或等待授权，自然语言不会发起第二个并发任务，也不会自动批准操作。一个明确的待回答问题可用自然语言回答；授权仍需明确卡片操作或 `/approve`。
- 一个话题对应一个当前任务。工作停止后，主人明确 @机器人或引用回复并点名另一个已授权项目，可在该话题切换项目并新建执行会话；旧任务与成果保留。不同群、不同话题的上下文分别隔离。

## 权限配置

已有应用在飞书开发者后台以**应用身份**开通：

| 权限 | 用途 |
| --- | --- |
| `application:bot.basic_info:read` | 读取机器人自己的 open_id，准确判断是否 @了本机器人 |
| `im:message.group_msg` | 接收群消息与话题后续回复；飞书将其标为敏感权限 |
| `im:message:readonly` | 读取来源消息、引用消息及群/话题历史 |
| `im:message.reactions:write_only` | 在主人的任务消息上添加“在做了”表情 |
| `im:message:send_as_bot` | 回复工作台和任务卡片，已有私聊模式通常已具备 |

继续使用已有 `im.message.receive_v1` 事件和 `card.action.trigger` 回调的长连接。如果后台提示需要发布或管理员审核，完成后再验证；权限面板开通不等于真实群链路已验收。群历史同时需要 `im:message:readonly` 和 `im:message.group_msg`，仅有群 @事件权限不足以读完整上下文。

官方资料：[群与话题历史接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)、[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[回复消息接口](https://open.feishu.cn/document/server-docs/im-v1/message/reply)。

## 上下文与授权边界

只有配置的主人可以创建任务、继续任务、停止、验收、答复权限请求或确认 PR。其他成员可以参与讨论，其消息被读作参考资料；其他成员或机器人的消息不能直接派活。即使处于已有任务话题，普通发言也会被忽略；只有主人 @本机器人、引用回复机器人已发送的消息，或回答同话题唯一一个待处理的工具输入问题时才触发。普通最终回复中的问句不会自动打开监听窗口，需要引用回复或 @机器人。@其他人的话题回复不会被机器人抢答。

派活和卡片来源由服务端保存，不接受表单伪造群 ID、话题 ID 或路径。读取上下文前核验来源消息所属群；话题无法读取时不改读整个群冒充成功。无法读取必要消息、缺少权限或超时时，任务失败并明确说明，模型不会在缺失上下文时悄悄继续。

上下文只读到本次指令或卡片提交时刻。每次最多扫描 3 页、每页 50 条，保留最近 20 条参考消息及必要的话题根消息和被引用消息，正文最多 16,000 字符，每条最多 2,000 字符。截断会在任务卡片和模型输入中注明。已撤回、其他群、其他话题和机器人自己的历史卡片会被过滤。卡片只提取可见文本，不执行按钮值。消息内容被明确标记为不可信参考资料，不提供授权。

群任务的结果、问题、卡片内容对该群/话题内能看到消息的人可见；只有主人的点击有效。不要把不适合群成员查看的项目任务派到群里。读取的参考消息保存在本机 SQLite，并传给该任务的 Codex 订阅会话；不会主动读取其他群，也没有全群长期归档器。

## 验收

1. 群里发一条不含敏感信息的测试背景，例如“这次按钮应该显示蓝色”。
2. 主人 @机器人派一个只读任务，要求结合前文复述需求；检查卡片显示读取范围和数量。
3. 在结果所在话题里直接发一句普通讨论，检查没有表情、模型调用或插话；再引用机器人的回复说“补充成两条验收标准”，检查任务 ID 不变、回复仍留在原话题。
4. 从卡片继续修改；在另一个话题发起新任务，检查两者没有混入上下文。
5. 可请另一名群成员尝试点击卡片，应得到仅主人可操作的提示。

6. 发带截图的富文本任务，要求复述页面标题及图表；后续引用回复应仍能看到最初截图。发送短视频时应能复述抽样画面和语音，明确指出抽样范围。

自动测试、后台权限开通、模型调用和真实群点击验收分别记录。他人派活和跨实例 agent 委派仍不在本轮范围。

## 附件读取范围

图片、PDF（含扫描页）、语音/音频和视频都支持读取。PDF 提取文字和页面图；音频使用本地 Whisper 转写；视频组合带时间点的抽样画面和语音转写。超页数、时长、数量、大小的部分明确标记未读取，不宣称完整看过或听过。详见[媒体读取和部署](media.md)。
