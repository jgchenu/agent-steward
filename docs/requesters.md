# 允许指定人员提交文字任务

默认只有主人能派活。主人可以在本机控制台的“谁可以向分身提交任务？”中添加指定人员，最多 50 人；不支持通配授权。

## 设置与使用

1. 让对方私聊**这一个机器人**发送 `/whoami`，把返回的应用内 `open_id` 发给主人。身份命令只返回发送者自己的 ID，不授予权限。
2. 主人在控制台填写备注名称与 `open_id`，保存并等待“已生效”。备注不用于匹配身份。不同机器人应用的 ID 不可混用。
3. 对方私聊发送文字需求，或在已启用群聊的群中 @机器人。机器人先回复“已提交给主人确认”，此时不创建执行任务、不调用模型。
4. 主人在机器人私聊收到申请卡，核对原文和结果接收位置后选择“接受并执行”或“拒绝”。也可以私聊发送 `/requests` 查看前 20 条待确认申请。确认有效期 24 小时。
5. 通过后，任务在主人的私聊中管理，结果返回请求者原私聊或原群话题。群话题的结果对群成员可见。额外权限和任务控制仍只允许主人操作。
6. 对方补充文字仍需主人确认，群聊中须再次 @机器人。对应任务的业务澄清可经确认后恢复；同一请求者、同一会话的后续需求复用该任务，其他人员、其他群话题及主人已有任务不共享会话。

当前只处理每次不超过 4000 字的文字。不会读取群历史或附件，不向来访者开放主人的代码项目或项目列表。需要代码、附件或业务系统数据时，由主人另行安排；现有机器人应用的可用范围、群消息权限和消息发送权限仍需配置。首次添加后请使用另一真实账号完成私聊、群聊与审批验收。

## 权限与恢复

- 请求者不能运行 `/edit`、`/list`、`/approve` 等主人命令，也不能操作任务卡片。`/whoami` 与请求说明不开放其他信息。
- 申请、原始文本、发送者、返回位置和确认结果持久化在 SQLite；重启不会丢失待确认申请。审批与创建或继续任务在同一事务中完成，重复消息、重复卡片不重复执行。
- 每个请求者在同一会话最多有一条待确认申请，每人最多五条，全实例最多一百条。达到上限时明确告知本条没有提交。
- 来访任务使用独立的通用只读目录与 Codex 会话，不提供代码资源选择。普通结果和业务澄清会发回请求者；工具请求、内部错误详情和管理卡片只发给主人。
- 主人通过 `/continue` 私下继续该任务时，不自动回传这轮结果；该会话之后也不再复用于来访者的新申请，避免将主人后续私聊内容带回外部。
- 删除人员并保存后，待处理申请失效，正在执行和等待中的相关申请任务停止，未发送的来访结果也会被丢弃。已发送内容无法撤回；已经在途的网络发送可能完成。
- 来访任务仍通过官方 Codex 执行。只读模式限制写入，不是对本机读取、浏览器或 MCP 的完整隔离；仅添加可信人员并在接受前核对请求。不会自动扩大执行权限或绕过工具本身的确认。

自动测试使用模拟执行器和模拟飞书 API，不代表真实飞书权限、消息可达性和双账号验收已经完成。
