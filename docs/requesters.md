# 允许指定人员直接使用分身

默认只有主人能派活。主人可在本机控制台“谁可以使用分身？”中添加最多 50 位可信人员；不支持通配授权。

## 设置与使用

1. 让对方私聊**这一个机器人**发送 `/whoami`，把返回的应用内 `open_id` 发给你。身份命令只返回发送者自己的 ID，不授予权限。
2. 在控制台填写备注名称和 `open_id`，保存并等待“已生效”。备注不参与授权匹配，不同机器人应用的 ID 不可混用。
3. 对方私聊发送需求，或在已启用群聊的群中 @机器人，任务直接进入执行队列，**无需你逐次确认接单**。
4. 对方可使用 `/projects`、`/new`、`/edit` 等现有入口，读取或修改你已经授权的代码项目；只读项目仍不能写入，工作副本/原目录方式和工具权限仍按你的设置执行。
5. 结果、澄清和审批留在发起人的原会话。对方可以回答问题、审批工具请求、确认自己任务的代码版本调整、草稿 PR 发布和 PR 合并。发布或合并仍须看到具体预览后确认；现有仓库检查与分支保护、staging 人工合并要求不变。
6. 私聊补充默认继续自己的最近任务；群内在原话题 @机器人继续。要在私聊另开任务，可使用 `/new` 或 `/edit`。同一人不同群话题、不同人及主人已有任务不共享执行会话。

## 权限边界

- 对方可使用控制台已经授权的全部代码项目，不能新增项目授权、修改人员名单、执行设置或后续任务的交付配置。请仅添加你信任其使用这些项目与本机工具的人。
- 只能查看、继续、取消和审批自己的任务。即使知道别人的任务 ID 或在群里看到别人的卡片，也不能操作；主人的原有任务权限不对外开放。
- 群内结果及审批详情对群成员可见。需要保密时使用私聊。本版仅使用指定人员提交的文字与已授权代码资源，不自动读取群历史或附件。
- 工具审批不等于授予全局权限；PR 发布、合并等仍是具体任务中的独立确认。机器人主人可在原会话查看和停止任务；绑定具体审批人的合并决定不能由另一人替代。
- 所有人共用配置台设置的执行并行数；代码任务与同一话题的执行仍然串行。
- 删除人员并保存后，会停止其正在执行与等待的任务，失效旧审批，并丢弃尚未发送的结果。重新添加不恢复旧任务和审批，可以重新派活。已有代码改动保留，已经在途的网络发送可能完成。
- 任务归属、撤销状态与审批记录保存在 SQLite，重启不会丢失。重复消息和重复审批不会重复创建任务或重复批准操作。
- 使用主人的 Codex 订阅与本机执行能力。会话与按钮隔离不等于独立容器；本机文件读取、浏览器与 MCP 仍有各自的权限边界。

自动测试使用模拟执行器、飞书 API 和 GitHub。部署后仍需用第二个真实账号验证私聊、群聊、代码任务、本人审批及越权拒绝；本地测试不代表真实飞书权限或消息可达性已验收。
