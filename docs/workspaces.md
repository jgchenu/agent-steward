# 工作空间授权与自然语言协作

在实例目录运行 `npm run workspaces`，打开终端显示的本机地址。页面显示名称、真实路径和当前权限，不需要修改 JSON 才能授权项目。

- **未授权**：只是候选目录，不进入机器人项目列表。
- **只读分析**：允许分析当前目录中的资料；默认不修改文件。
- **允许修改**：当前仅支持 Git 仓库根目录。机器人使用独立 worktree，不直接覆盖你的工作目录。新授权从当前本地分支的已提交内容开始；如果目录处于 detached HEAD（没有分支名），则固定使用授权时的当前提交，不带入未提交改动；已有项目的工作目录与检查配置保持不变。
- **默认空间**：没有明确提及其他项目时使用。建议把通用分析目录设为默认。

保存是授权生效的动作；添加候选或改变尚未保存的下拉选项不会授权。运行中的机器人会在下一条事件前或约一秒内更新项目范围。撤销、变更路径或把修改权限降为只读，会中止不再被允许的活跃执行，已有改动保留。无效配置不会替换最后的有效配置。

页面可添加本机已有目录。也可由已授权的桌面工具读取 Codex 项目名称与路径，再导入私有 `<stateDir>/workspace-catalog.json`（数组项为 `id`、`label`、`path`，可选 `description`）。仅导入元信息，不自动授权、不读取 Codex 登录凭据或私人聊天。多个展示项目指向同一目录时合并为一项。跨主机和云项目当前不支持。

直接发消息即可工作，例如：

- `@机器人 分析上面讨论的方案，列出利弊` → 默认分析空间。
- `@机器人 看看 内容写作 的现有大纲，给我修改建议` → 名称明确匹配的已授权项目。
- 同时提到多个已授权项目 → 点选本次目标，不必重填需求。
- 在已有任务的话题里回复新要求 → 同一任务、项目、模式和 Codex 会话继续。

路由目前匹配明确的项目名称/别名，并使用默认空间，不是任意语义的项目识别。只在主人本次消息中判断项目，不让其他成员的上下文代替主人选择工作目录。需要跨项目工作的任务暂不支持一次自动切换多个项目。

授权页选择“允许修改”也会将该项目的自然语言任务模式设为允许修改；Codex 的具体工具审批仍由主人确认。手动配置可使用 `naturalMode: "read-only"` 保持自然语言只读，同时保留手动修改能力。任务开始后模式不随续聊自动升级。

任务前先添加“在做了”表情，完成后在话题内交付结果。平台需开启 `im:message.reactions:write_only`；[官方表情接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message-reaction/create)。缺少权限时使用简短话题回执。

新授权的代码项目没有自动猜测测试命令或 GitHub 目标。修改结果可查看，但发布 PR 仍需要[配置检查与目标](project-delivery.md)并单独确认；不会自动合并或部署。普通非 Git 文档目录的原位写入与完整 Codex 聊天历史同步尚未实现。

本地页面只监听 127.0.0.1，不要通过代理公开到互联网。它面向运行实例的本机使用者，不能隔离同一系统账户下的恶意进程。项目授权限制调度范围；Codex 自身的本机工具/MCP 权限仍然生效，不应将它视为操作系统级目录沙箱。
