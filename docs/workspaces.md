# Codex 项目与对话

空间和代码项目不是创建任务的前置条件。归纳材料、业务分析和内容整理可以直接发给分身；本页的项目授权仅用于确实需要读取或修改代码的工作。控制台的项目默认值不替代模型对资源必要性的判断。

分身服务启动后，直接在同一台电脑打开 **http://127.0.0.1:17831/**，可收藏到浏览器书签。macOS 用户也可把仓库中 `shortcuts/打开分身控制台.webloc` 放到桌面，双击打开；它只打开网页，不会自动启动服务。控制台随服务一起启动和关闭，无需另开终端。也可以私聊分身“打开控制台”取得入口；群里需 @ 分身。链接只适用于运行分身的电脑，手机或其他电脑不能访问。

首次安装和启动仍需部署者完成；本版本没有安装包、菜单栏程序或开机自启。只管理配置而不运行机器人时，部署者仍可使用 `npm run workspaces` 启动独立控制台；它与机器人使用同一端口，不能同时运行，端口冲突会明确失败而不会悄悄改地址。

## 模型与思考强度

控制台通过 Codex App Server 的 `model/list` 读取模型和各自支持的强度，不硬编码型号或假定所有模型都支持最高强度。切换模型时使用该模型返回的默认强度，可继续调整后保存。模型读取失败可重试，不影响现有权限设置；保存新组合和执行时都会重新校验，模型下线或组合失效会明确失败，不自动替换或回退 API。

未指定模型时保持原有行为：新会话采用 Codex 本机设置，旧会话沿用会话设置。一旦在控制台明确选择，所有后续任务与继续对话的下一轮均使用保存的模型和强度；正在执行的本轮不受影响。运行时状态展示已应用设置，模型选择记录在本地任务事件中。模型目录并不保证账号有无限额度或实际调用权限。

## Codex 项目

项目列表通过 Codex App Server 的 `project/list` 读取，约十秒同步；只读取项目身份、名称和根目录，不读取登录凭据或私人聊天。请在 Codex 中添加、移除和命名项目，控制台不再维护额外目录清单。

列表与授权分开：新增项目默认未授权。授权绑定 Codex 项目 ID 与主目录；同一目录出现在多个项目里不会连带授权。多目录项目显示为一个 Codex 项目，目前仅支持其第一个根目录，关联目录不会自动授权或作为执行目录。远程/云项目不在本机 App Server 清单中。

- **未授权**：分身不能调度该项目。
- **仅查看**：读取和分析项目，不修改文件。
- **编辑原目录**：直接使用原项目目录，支持普通文件夹和未提交过的 Git 仓库。修改立即写入当前目录，保留已有文件；所有代码任务依次执行。
- **编辑独立副本**：Git 仓库中建立独立工作副本。基于当前分支的已提交内容（detached HEAD 固定提交），不带入未提交改动。既有基线、检查命令与 PR 配置继续保留。

只有可读取提交的 Git 根目录才显示“编辑独立副本”。普通目录和空 Git 仓库只显示未授权、仅查看、编辑原目录。配置仍采用整体校验，保存失败不会部分写入授权。

直接编辑不会自动初始化 Git、创建副本或提供自动 PR 交付，也不生成 Steward 独立检查报告；执行 Agent 可运行项目检查并报告实际结果。现有副本配置在切换时保留，但仅在副本模式下使用。切换执行位置会停止受影响的执行；已开始的任务不能在原目录和副本间搬移会话，需要新建任务，已有改动保留。审批方式和目录授权继续生效。

保存后机器人热更新；移除项目、撤销授权或收紧权限会停止不再被允许的执行，保留任务历史及已有文件。项目接口暂不可用时不退回旧候选列表，代码调度关闭，聊天仍可用。主机内已经运行的旧服务需要更新一次才能支持新行为。

## 不需要默认项目

普通聊天、群消息总结和附件分析没有代码项目。执行器所需的内部临时目录不出现在项目列表，不获得代码修改权限，也不受“不限制写入目录”档位提升。

- `分析上面的讨论，给两条建议`：直接处理消息和附件，不选择仓库。
- `看看 TikSight 的登录流程`：匹配已授权的项目名称或别名，进入该项目。
- `修复这个组件`：没有明确项目时询问本次目标，即使只授权一个项目也不擅自选择。
- 同一话题继续讨论：沿用已确定的项目；明确提到另一个项目时进行独立会话交接。未授权项目先说明授权缺失，不落入聊天目录执行代码。

识别目前使用明确名称/别名与保守的代码意图规则，不是完整语义分类。难以判断的聊天执行器也被要求先澄清代码目标，不能自行扫描本机仓库。群上下文和附件属于参考材料，不替代主人授权。

## 迁移与权限

启动时读取成功的 Codex 项目清单，将可唯一对应的旧授权固定到 Codex 身份，移除不属于 Codex 的历史目录及默认项目设置。原私有配置保存在 `steward.config.json.before-codex-projects.json`（或自定义配置路径加同后缀）。旧任务和文件不会删除；移除项目的旧任务不可继续执行，需明确选择已授权项目。“通用分析”和分身源码不会自动成为 Codex 项目。

审批方式仍在同一控制台设置，详见 [执行审批](project-delivery.md#减少执行过程中的手动审批)。控制台只监听本机，保留同源、令牌及配置修订校验。项目清单决定任务调度范围，并不是完整的操作系统文件隔离；完全访问的代码任务仍需理解其实际访问范围。

## 限定目录内执行

常用模式为“需要额外权限时询问”“自动审查权限请求”“限定目录内执行”。最后一档允许已授权修改任务在授权的执行目录内写文件、运行检查并联网，Codex 执行权限不再逐次询问；越界直接失败，不自动提权。只读任务仍只读且不自动开放网络。完全访问本机放在高级设置，仍需明确确认。

这里是写入沙箱，不是独立虚拟机，也不声称隔离所有本机读取、浏览器或 MCP。联网请求和工具本身的授权边界仍然适用；浏览器确认、创建草稿 PR 的发布确认和独立合并确认保留。当前执行不会因切换更宽松的模式而提权。

分身子进程只屏蔽本机已识别的 CodeIsland `PermissionRequest` 弹窗钩子，原 Codex 的全局配置不修改，日常桌面 Codex 仍可使用 CodeIsland。自定义命令包装、插件或内联钩子不自动屏蔽；不使用关闭全部钩子的回退方案。


## 并行任务数

配置台“同时处理几个任务？”可选择 1–4，默认 2。保存沿用现有配置版本检查，页面分别显示已保存上限、运行服务实际应用的上限和当前执行数量。服务未连接或版本尚未上报时，不会显示为已生效。

保存后自动应用，无需重启。调高上限会放行符合条件的排队任务；调低上限不会停止现有任务，等执行数量低于新上限后再启动下一项。所有代码/Git 任务仍串行，同一任务、话题和 Codex 会话也不会并行。修改此设置不扩大任何项目或工具授权。


## 谁可以使用分身

控制台可维护最多 50 位可信人员的备注与飞书 open_id；默认空列表，仅主人可用。对方先私聊此机器人发送 `/whoami` 获取身份 ID。保存后热更新，页面区分未保存、等待应用和已生效。添加后对方可直接派活、使用已授权的代码项目，并审批自己的任务；无需主人逐次确认。项目读写与执行目录沿用现有授权，对方不能修改控制台或操作他人的任务。删除人员会停止其执行、使旧审批失效。详见[人员授权](requesters.md)。
