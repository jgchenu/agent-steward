# Codex 项目与对话

在实例目录运行 `npm run workspaces`，打开本机控制台。项目列表通过 Codex App Server 的 `project/list` 读取，约十秒同步；只读取项目身份、名称和根目录，不读取登录凭据或私人聊天。请在 Codex 中添加、移除和命名项目，控制台不再维护额外目录清单。

列表与授权分开：新增项目默认未授权。授权绑定 Codex 项目 ID 与主目录；同一目录出现在多个项目里不会连带授权。多目录项目显示为一个 Codex 项目，目前仅支持其第一个根目录，关联目录不会自动授权或作为执行目录。远程/云项目不在本机 App Server 清单中。

- **未授权**：分身不能调度该项目。
- **只读分析**：在已授权项目中分析资料。
- **允许修改**：Git 仓库中建立独立工作副本。基于当前分支的已提交内容（detached HEAD 固定提交），不带入未提交改动。既有基线、检查命令与 PR 配置继续保留。

保存后机器人热更新；移除项目、撤销授权或收紧权限会停止不再被允许的执行，保留任务历史及已有文件。项目接口暂不可用时不退回旧候选列表，代码调度关闭，聊天仍可用。主机内已经运行的旧服务需要更新一次才能支持新行为。

## 不需要默认项目

普通聊天、群消息总结和附件分析没有代码项目。执行器所需的内部临时目录不出现在项目列表，不获得代码修改权限，也不受“完全访问权限”档位提升。

- `分析上面的讨论，给两条建议`：直接处理消息和附件，不选择仓库。
- `看看 TikSight 的登录流程`：匹配已授权的项目名称或别名，进入该项目。
- `修复这个组件`：没有明确项目时询问本次目标，即使只授权一个项目也不擅自选择。
- 同一话题继续讨论：沿用已确定的项目；明确提到另一个项目时进行独立会话交接。未授权项目先说明授权缺失，不落入聊天目录执行代码。

识别目前使用明确名称/别名与保守的代码意图规则，不是完整语义分类。难以判断的聊天执行器也被要求先澄清代码目标，不能自行扫描本机仓库。群上下文和附件属于参考材料，不替代主人授权。

## 迁移与权限

启动时读取成功的 Codex 项目清单，将可唯一对应的旧授权固定到 Codex 身份，移除不属于 Codex 的历史目录及默认项目设置。原私有配置保存在 `steward.config.json.before-codex-projects.json`（或自定义配置路径加同后缀）。旧任务和文件不会删除；移除项目的旧任务不可继续执行，需明确选择已授权项目。“通用分析”和分身源码不会自动成为 Codex 项目。

三档审批方式仍在同一控制台设置，详见 [执行审批](project-delivery.md#减少执行过程中的手动审批)。控制台只监听本机，保留同源、令牌及配置修订校验。项目清单决定任务调度范围，并不是完整的操作系统文件隔离；完全访问的代码任务仍需理解其实际访问范围。
